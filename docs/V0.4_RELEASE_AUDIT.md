# V0.4 Release Audit — Frontend Integration

## 1. Release Overview

V0.4 introduces a React and TypeScript frontend integrated with the existing
V0.3.1 FastAPI execution backend and V0.2 synthetic-data engine.

The release builds on the existing architecture rather than replacing the
synthetic-data engine or the execution backend.

## 2. Architecture

- Frontend: React, TypeScript, Vite
- Backend: FastAPI, Python 3.12
- Generation: SDV / CTGAN
- Job metadata: SQLite
- Job execution: In-process queue and background worker
- Artifacts: Local filesystem
- Frontend API prefix: /api/v1/
- Development frontend: http://localhost:5173/
- Development backend: http://127.0.0.1:8000/

The Vite development server proxies requests beginning with /api to the
local backend.

## 3. Frontend Integration

The frontend contains:

- Dashboard summary metrics
- Job listing and status visibility
- CSV upload and requested row count
- Job status monitoring
- Artifact listing and downloads

The dashboard summary endpoint is:

GET /api/v1/dashboard/summary

Other backend endpoints cover health, readiness, version, job creation,
job status, artifact listing, and artifact downloads.

## 5. Existing Architecture and Limitations

- The job queue is in-memory.
- The worker runs within the API process.
- Job metadata uses SQLite.
- Generated artifacts use local filesystem storage.
- Distributed worker execution and horizontal scaling are not implemented.
- Production authentication, authorization, multi-tenancy, and enterprise
  deployment capabilities are outside the current scope.
- A successful privacy evaluation is not legal or regulatory certification
  and does not guarantee protection against every privacy attack.

## 6. Known Verification Considerations

- A successful frontend build does not by itself prove every user workflow.
- Backend connectivity and generation depend on the backend being available.
- Job execution failures may occur for unsuitable input data or generation
  constraints.
- An intermittent same-seed test failure was previously observed; its
  underlying cause remains unconfirmed.
- Dashboard summary values should be interpreted according to the API's
  implemented counting logic.
